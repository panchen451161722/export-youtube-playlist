# Playlist Backup release preparation

## Scope

Playlist Backup landing page and separate interactive demo; collection cards and
notification preferences; encrypted YouTube account connections; annual-only
Stripe checkout and customer portal. Existing monthly subscribers retain their
entitlements. English and Chinese content are included.

## Database

The user reviewed and approved `0001_eminent_jasper_sitwell.sql` on 2026-10-15.
Its committed copy is in `docs/deployment/migrations/`. The generated `drizzle/`
directory is ignored by this repository. Use the exact same migration filename
when reconstructing that directory; check D1's migration history before applying.

This migration only creates `guard_collection`, `guard_workspace`,
`guard_delivery`, `youtube_connection` and their indexes. It does not rewrite
existing tables or import local data. Applying it to an in-memory copy of the
production schema preserved all existing schema objects and passed foreign-key
checks. Production application and deployment are the next release operations.

## Validation

- All 81 automated tests passed.
- `pnpm build` and `pnpm exec tsc --noEmit` passed.
- Local public routes, English/Chinese backup pages, pricing, demo, sitemap and
  robots returned HTTP 200. Backup is indexable; pricing remains noindex; demo
  remains noindex.
- Browser spot checks covered responsive pricing and backup layouts, light/dark
  themes and navigation to the independent demo. No horizontal overflow was
  observed at the tested 480, 768 and 1440 CSS-pixel widths. The browser's minimum
  width prevented an exact 390-pixel check. This is not an exhaustive route audit
  or a production Lighthouse/Core Web Vitals measurement.
- Security review covered credentials, authorization, OAuth state and encryption,
  webhook signatures, payment amounts, ownership and idempotency. Scanner matches
  for three test `clientSecret` fixtures are obvious placeholders in mocked tests,
  not credentials. No actionable security finding remained.

## Production handoff

Deploy with `pnpm run cf:deploy` so the production origin is used by the Cloudflare
build. Keep the existing authentication and config-encryption secrets stable.
Do not copy local databases, test accounts, or payment secrets into production.

The live Stripe catalog and customer portal already exist. The live webhook is
disabled pending guided production configuration. After deployment, configure the
website key, matching webhook secret, price mapping and portal configuration in
the online admin panel, then enable and verify checkout and webhook delivery.
Local test-mode checkout acceptance is documented in `docs/research/stripe-annual.md`;
it does not substitute for production verification.

YouTube OAuth callbacks, Resend, and scheduler activation need their production
configuration. Deploying the code alone does not activate automatic checks or
email delivery. Scheduler activation requires its enable flag and job secret.
